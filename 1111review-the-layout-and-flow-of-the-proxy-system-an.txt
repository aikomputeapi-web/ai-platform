● I've traced the full proxy system end to end. Here's my assessment.

  The core problem: two implementations disagree, and the running one is the 
  broken one

  There are two copies of the 3-tier logic in this repo:

  - OmniRoute/src/lib/jobs/freeProxyJob.ts — the one actually running (wired in
  server-init.ts / instrumentation-node.ts).
  - proxy-tool-reuseable/src/core/ticks.ts + promoteDemote.ts — a later,
  cleaned-up extraction that fixes several of the bugs below but is not wired 
  into OmniRoute (its own README says "OmniRoute itself is NOT modified").

  So the corrected design already exists in your repo — it just isn't the code
  serving traffic. Most of what follows is "the live job diverged from its own
  documented design, and the fixed version is sitting unused next to it." That
  framing matters for the fix: much of this is porting the package's logic back
  into the live job, not inventing anything.

  Below, ordered by how directly each one fights your 100%-uptime goal.

  ---
  1. Tier 3 failure dumps proven proxies straight back to intake (biggest flow 
  break)

  The job's docstring and the README both say the cascade is Tier 3 → Tier 2 → 
  Tier 1: a live proxy that fails once drops to testing (Tier 2), and only if it
  immediately fails again falls to intake. The extracted package implements
  exactly that (demoteTier3Proxy(..., targetTier: 2, failureHeadStart: 
  tier2Demote-1)).

  The live job does not. demoteTier3ToTier1() (freeProxyJob.ts:378) deletes the
  registry row and drops the proxy straight to Tier 1, resetting all counters. A
  proxy with months of proven history that has one transient blip must now
  re-earn 5 Tier-1 successes and full Tier-2 verification before it can serve
  again. This churns the live pool hard and is the single biggest thing working
  against uptime — the "testing" safety-net tier is skipped entirely on the way
  down.

  2. The testing→live promotion path is effectively starved

  Two compounding issues mean Tier 2 rarely feeds Tier 3:

  - The fast path is dead. In the live check tick (every 5 min), the Tier 2
  section records successes but never promotes — it only demotes.
  consecutive_successes accumulates and nothing reads it. tier2PromoteThreshold
  (default 10) is parsed into settings and never used anywhere. The package's
  Tick does promote here (newSuccessCount >= tier2PromoteThreshold). This is the
  primary verified→live path, and in production it doesn't exist.
  - The slow path is nearly unreachable. The only live promotion is in the sync
  tick (every 30 min), gated on success_count = test_count — a perfect lifetime
  record. But recordFreeProxyTestResult counts cumulatively and never resets on
  the success path, so the first time a Tier 2 proxy fails a single check (below
  the 3-strike demote threshold), success_count != test_count forever. That
  proxy can never be promoted, yet stays in Tier 2 being re-tested indefinitely
  — a permanent limbo.

  Net: the global pool only refills every 30 minutes, only with spotless-history
  proxies, while Tier 3 is draining every 5 minutes via issue #1. That
  imbalance is why the pool trends toward empty.

  3. "Alive" is defined two different ways, and they disagree

  - Tier demotion uses testProxyMultiTarget — a HEAD request to
  openai/anthropic/aws, "any response = ok."
  - The same tick also runs validateProxyPool (proxyEgress.ts), which uses an
  ipify egress echo and writes proxy_registry.status.
  - Runtime request resolution (PROXY_ALIVE_PREDICATE, proxies.ts:507) routes on
  status — i.e. the ipify definition.

  So a proxy can reach Anthropic fine but fail ipify (or vice versa) and end up
  marked error and pulled from rotation, or kept active after being
  tier-demoted. The tier state and the routing state are set by different probes
  against different endpoints. Pick one definition of "working" and drive both
  from it.

  4. Demotion leaves accounts routed to nothing until the next sync

  demoteTier3ToTier1 deletes all proxy_assignments for that proxy, including
  account-scope ones. Redistribution only runs in the sync tick (every 30 min)
  and only when autoDistribute is on. So a demoted live proxy can leave a
  provider account with no egress proxy for up to 30 minutes, with no immediate
  backfill from Tier 2. For a system whose entire reason to exist is egress-IP
  continuity, that's a real gap.

  5. Latency measurement penalizes good non-OpenAI proxies

  testProxyMultiTarget starts one timer before the target loop and returns
  Date.now() - start on the first reachable target. A proxy that can't reach
  OpenAI (5s timeout) but reaches Anthropic instantly is recorded at ~5000ms
  latency → computeQualityScore gives it ~35 → it falls below minQuality (40)
  and is blocked from promotion. You're filtering out working proxies because an
  earlier, unrelated target timed out. Measure per-successful-target latency,
  not wall-clock across failures.

  6. Smaller seams

  - Dead settings in the control UI. minSuccessRate, autoElevate,
  autoRemoveDead, tier2PromoteThreshold are all parsed and surfaced through
  proxyControlService.ts but never consumed by the job. Operators tune knobs
  that do nothing.
  - Low-pool alert is hardcoded at 3 regardless of poolSize (configurable up
  to 50). The pool can sit 90% empty and never alert.
  - Tier 1 is tested exhaustively with no cap. Intake can be thousands of
  freshly-scraped proxies; at 3 targets × 5s each it can blow the tick's runtime
  and trip the isCheckTickRunning overlap guard. Tier 1 runs last in the tick
  so it can't starve Tier 3/2, but a tick that never finishes still delays the
  next cycle. Cap intake testing per tick.

  ---
  Recommended path

  The cleanest fix is to make the live job match the extracted package rather
  than patch each symptom, since the package already encodes the corrected
  cascade and promotion logic. Concretely, in priority order:

  1. Change Tier 3 demotion to target Tier 2 with a pre-seeded failure
  head-start (port demoteTier3Proxy), and add the missing Tier-2→Tier-3
  consecutive-success promotion to the check tick.
  2. On demotion, immediately backfill the vacated slot/assignment from the best
  Tier 2 candidate instead of waiting for the sync tick.
  3. Unify the liveness probe so tier state and proxy_registry.status come from
  the same test.
  4. Fix the latency measurement, wire up (or remove) the dead settings, and
  scale the low-pool alert to poolSize.
